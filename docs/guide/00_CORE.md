# 00 CORE — 원칙·정책·제작 순서

## 1. 채널 정의

| 라인 | 장르 | 언어 | 시청 상황 예시 |
|---|---|---|---|
| JP | 칠팝·시티팝 | 일본어 문구 | 밤 드라이브, 新宿の夜, 雨の日のカフェ, 作業用 |
| KR | 팝 | 한국어 문구 | 출근길, 카페 작업, 퇴근 후 산책, 공부 |

한 영상 = **한 장면(언제·어디서·어떤 기분)**. 장르만 있는 플리("시티팝 모음")는 만들지 않는다.

## 2. 정책 (2026-07 YouTube inauthentic content 기준)

수익화가 막히는 패턴과 피하는 방법:

| 막히는 패턴 | 우리가 하는 것 |
|---|---|
| 같은 템플릿·같은 그림에 곡만 바꾼 영상 | 영상마다 다른 장면 콘셉트와 비주얼 |
| AI 곡 무작위 나열 | 곡 순서에 이유가 있음(01_CURATION 흐름 설계), 설명란에 큐레이션 노트 |
| 대량 업로드 | 주 1~2편, 품질 우선 |
| AI 사용 숨김 | 변경·합성 콘텐츠 공개 + 설명란 표기 |

## 3. 권리 원칙

- 출처·플랜·생성일·권리 근거가 `tracks/tracks.csv`에 기록된 곡만 쓴다.
- 권리가 애매하면 `rights=hold`. 빌드에서 자동 제외되지 않고 **빌드 자체가 실패**한다(실수 방지).
- 자세한 기준은 02_MUSIC_SOURCING.

## 4. 제작 순서 (단계마다 사용자 확정)

1. **콘셉트** — 장면 한 줄 + 타깃 라인(JP/KR) + 길이 (01)
2. **트랙리스트** — 대장에서 곡 선택, 흐름 설계, `playlist.yaml` 작성 (01)
3. **음원 보충** — 모자란 곡 생성·의뢰, 대장 등록 (02)
4. **비주얼** — 장면 이미지/루프 영상 (03)
5. **렌더링** — `scripts/build_playlist.py` (03)
6. **업로드 문구** — 제목·설명·챕터·태그, 체크리스트 (04)
7. **성과 기록** — 7일·28일 (04)

## 5. 길이

- 기본 **60분 전후**(15~20곡). 작업용·수면용은 90~180분까지.
- 같은 곡을 한 영상에서 반복하지 않는다. 길이가 모자라면 곡을 더 만든다.
